## 已完成并验证的代码

- 首次报名成功写入永久推荐关系，沿用每客户唯一推荐人的数据库约束。重复报名、取消后报名、后续邀请链接均不能改绑。原有推荐关系保留。
- 代理通过 `service_provider.service_kind=AGENT` 标识，由具有现有管理能力的工作人员指定。客户端 `account.user_type` 不参与授权。代理即使被错误配置了工作人员能力标记，动作流也不会赋予其工作人员权限。
- 代理只能读取本人推荐客户的基本信息和报名状态，不能查看孩子资料。取消代理资格后停止其邀请和名单访问，原客户归属仍保留。
- 孩子表单保存请求包含孩子姓名、性别、年龄、年级、经济来源、恰好两个不同的问题选项、问题描述、日常表现、家长姓名、联系电话和监护人同意。
- 一次报名对应一次资料提交。家长本人和该课程负责且具有回复能力的工作人员可读取，其他客户、代理和其他课程工作人员均被拒绝。
- 工作人员保存草稿、确认完成分别处理。确认时由服务器写入完成时间及其后3小时的可查看时间，客户端不能指定时间。反馈确认后不可覆盖；草稿并发更新检查版本。
- 等待期客户接口不查询或返回反馈正文；到时后再次读取才会返回。测试覆盖可查看时间的前1毫秒和准确边界，以及伪造时间、重复提交、越权、取消重报。
- 小程序原页面和工具代码未修改。

## 恢复后的执行顺序

1. 编辑器关闭上表列出的默认权限，并通过 schema snapshot 回读；运行 `python3 scripts/extend_referral_intake.py` 通过权限检查。
2. 运行 `python3 scripts/update_consultation_code.py`，验证现有动作流节点及完整 schema。确认安全权限后同步后台。
3. 用合成账号实测角色、字段、推荐唯一约束、手动反馈及3小时隐藏，再连接网页；测试记录与真实业务数据分开。
4. H5 登录回调移除独立锁定推荐人的调用，改为签名邀请候选；报名时把有效候选传入 `ENROLL`。当前 H5 尚未修改，不能仅部署新动作流就宣告功能完成。
5. H5 bootstrap 按身份请求名单，普通客户不请求 `MY_REFERRALS`。新增业务接口须验证登录及请求来源。
6. 网页补充推荐人/代理客户列表、管理人员指定代理、报名后孩子资料链接及本地生成二维码、家长表单和工作人员草稿/确认入口。二维码只是定位报名，扫码后仍验证本人身份。
7. 检查移动端完整流程、GitHub 上传与正式域名部署。原小程序源代码保持不变。
