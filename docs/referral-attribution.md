# 网页推荐归属

## 使用入口

- 管理和代理：`我的 → 推荐客户 → 生成图片`，生成本人签名推荐二维码图片；课程详情的「分享报名码」可生成指定场次的邀请图片。长按保存后发送至微信，不在图片中展示长链接。
- 未登录客户扫码后先进入微信登录页；授权完成返回原课程。刷新、授权失败重试或返回无参数首页都保留推荐来源，不直接当作无推荐的访客放行；二维码失效时明确提示联系分享人重新生成。
- 代理只看本人客户；管理可切换到全部推荐客户。列表展示推荐人、报名人、最近 20 条课程报名及到课状态，客户列表支持翻页。
- 新客户扫码后首次成功报名才写入既有 `course_referral` 表；付费场次等待支付验签及成功报名。打开链接、登录、未支付或报名失败均不建立关系。
- 已绑定关系不被新链接覆盖。已有报名但未记录推荐人的历史客户不自动归属，不能根据本次访问推断历史来源。

## 实现与安全

- H5 `referral-context` 从 Zion 当前身份确认邀请权限，服务端以登录账号生成签名，不接受客户端指定的代理身份。
- `capture-referral` 在页面跳转前验签，以 30 天 HttpOnly / SameSite=Lax 签名 Cookie 保存邀请。登录后绑定账号，退出时清理；登录过期后可恢复同一账号的邀请，但换号不会继承原账号来源。已登录用户扫码不清空现有登录，也不延长原登录有效期。
- `ENROLL` 通过同源 `/api/h5?action=enroll`，付费报名通过已有 `course-pay`；服务端校验 URL 推荐码，或恢复邀请 Cookie / OAuth 会话中保留的推荐人。已存在的客户归属仍以 Zion 为准，邀请 Cookie 不是最终归属记录。
- OAuth 仅恢复白名单中的本地课程或广场路径；普通用户转发时使用服务端恢复的签名推荐码，代理分享优先使用自己的身份。
- `REFERRAL_OVERVIEW` 和 `REFERRAL_CLIENTS` 是既有同步业务动作流中的守卫操作；不新增表，不放开直接数据权限，不返回电话或孩子资料。
- `scripts/stage-course-referrals.js` 只替换经过定位的授权／推荐／免费报名代码段，保留线上支付代码、密钥绑定和其他并发代码；随后验证并同步 Zion 后端。脚本拒绝重复覆盖已添加的推荐段。
- 默认完整构建器也包含新推荐处理器，防止后续发布丢失。

## 验证

权限与归属、跨登录 / 刷新 / 无参数访问 / 重试 / 换号、免费与付费报名、完整 PNG 二维码独立解码、网页入口／实际列表渲染、分页及已有测试均由 `scripts/tests/` 覆盖。OAuth 自动化使用模拟微信响应，不等同于手机微信实测。本地视觉检查使用合成数据，不向生产写入测试报名；演示二维码不能作为正式报名图片发送。
