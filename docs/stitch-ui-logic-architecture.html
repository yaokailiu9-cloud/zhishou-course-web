用户预约主流程

这是当前代码里最关键的链路：所有“预约”按钮都应该把用户带到底部导航第二页，而不是停留在首页。

01
首页发现
用户通过搜索、推荐咨询师或专题入口产生预约意图。
02
选择咨询师
点击咨询师卡片查看详情，或直接点击“立即预约”。
03
预约确认
进入 Tab 第二页，选择日期和时间，底部展示 ¥200 总费用。
04
支付咨询
确认支付后创建订单和咨询会话，跳转到聊天页开始服务。

核心状态机

设计时需要让用户清楚知道当前处在哪一步：未预约、待接单、服务中或已结束。

订单状态

created 待支付 → paid 已支付 → active 服务中 → finished 已完成

会话状态

waiting 等待接单 → active 正在咨询 → closed 服务结束

数据对象给 UI 的含义

Stitch 不需要关心数据库细节，但需要知道每个页面展示哪些业务信息。

advisor 咨询师

  • 姓名、头衔、头像
  • 评分、已帮助人数
  • 擅长标签、服务简介
  • 统一价格 ¥200/小时

consultation_order 订单

  • 金额、时长、支付状态
  • 咨询师、客户、问题备注
  • 支付时间、有效截止时间

consultation_session 会话

  • 等待接单 / 服务中 / 已结束
  • 经理、客户、会话主题
  • 最近消息和剩余服务时间
