# 免费公开课与线下咨询服务流程

记录日期：2026-09-08。依据本次口述及后续澄清整理。本文为业务要求与实施方案；前端代码及 Zion 编辑草稿已实现，正式后端同步与真实联调尚未完成，不代表已上线。项目为情感对话小程序 `JmAxbl1MMe4`。

## 1. 本次确定的范围

- 公开课免费，报名留下姓名和手机号。此前提到的 100 元场地费不纳入当前流程。
- 用户必须实际参加过公开课，才可以申请线下咨询；报名提交不等于参加课程，更不等于预约成功。
- 工作人员核实参加情况并确认咨询安排。
- 内部付费课程暂缓，本次不接入收费、扫码购课或付费资格门槛。
- 预约确认后填写孩子基础信息；到店沟通后由老师整理记录和执行建议。
- 家长持续反馈执行情况，老师可以查看并逐条回复。
- 沟通总结同时支持本次预约内的文字留言/反馈/回复与线下面谈录音转写，均由老师检查确认。

## 2. 主流程与状态

免费公开课报名 → 工作人员邀请进群 → 群内通知课程地址 → 参加公开课 → 工作人员核实到课 → 提交线下咨询申请 → 工作人员确认时间 → 填写孩子基础信息 → 到店咨询 → 老师整理沟通记录与执行建议 → 家长反馈 → 老师回复 → 持续执行和复访。

| 业务环节 | 状态与含义 |
| --- | --- |
| 公开课报名 | 已报名、已取消；不创建支付单 |
| 公开课参加 | 待参加、已参加、缺席；只有工作人员核实后才记为已参加 |
| 进群跟进 | 待联系、已邀请、已进群；展示实际跟进状态 |
| 线下预约 | 待确认、已确认、已取消、已完成；工作人员确认具体时间后才称预约成功 |
| 孩子基础信息 | 待填写、已提交；预约成功后、到店前完成 |
| 沟通记录 | 草稿、已确认；老师确认后向家长展示 |
| 执行反馈 | 待回复、已回复；家长新增补充后再次进入待回复 |

## 3. 免费公开课报名

提供可分享的报名入口，优先使用小程序分享卡片，也可展示工作人员提供的公开课链接。报名页明确展示“免费公开课”、课程名称、场次时间、姓名和手机号输入框，以及“提交报名”按钮。

报名成功后展示进群指引：“请按提示联系工作人员进群，课程地址将在群内通知。”小程序不把提交报名显示成自动进群成功。工作人员在报名名单中查看姓名、手机号，联系并邀请家长进群，核实实际到课。

未提供课程场次、链接或进群二维码时展示待安排状态，不填入虚构时间、地址或二维码。重复提交应返回同一报名结果，避免产生重复名单。

## 4. 预约资格与线下安排

参加过公开课是申请线下咨询的必要条件。后端根据工作人员确认的真实参加记录校验资格；不能依据用户自行勾选“我已上课”、报名记录或本地缓存放行。

- 未报名：引导报名免费公开课。
- 已报名、未确认到课：展示“参加公开课后可申请线下沟通”，可查看报名与进群说明。
- 已核实参加：开放申请咨询入口。
- 已提交申请：显示“待工作人员确认”，不能直接显示预约成功。
- 工作人员确认老师和时间后：显示“预约成功”，引导填写孩子基础信息。

线下咨询是否另收费、时长、可选时段和改期规则尚未指定，不沿用旧代码中的“200 元/60 分钟文字咨询”规则。再次预约也保留工作人员确认流程；无需重复参加公开课的具体有效期规则待运营决定，不预设过期时限。

## 5. 孩子基础信息

页面名称使用“孩子基础信息”。预约确认后填写，到店前完成。建议字段为孩子姓名/称呼、年龄或出生日期、年级、家长姓名、与孩子关系、联系电话、当前主要困扰和希望本次沟通解决的问题；最终必填字段待业务提供。

一位家长可以有多个孩子，每次预约必须关联明确的孩子。本次提交内容保留快照，后续改资料不覆盖历史咨询背景。填写完成不触发“咨询完成”。

## 6. 咨询记录与执行建议

每次咨询单独保存，按日期排列在对应孩子基础信息之后。老师填写本次主要问题、沟通内容、结论与执行建议，并在实际沟通结束后标记咨询完成。

执行建议逐条列出具体做法。若“执行哪几段”指课程章节，可以关联对应章节并补充文字说明；不因此提前引入付费课程流程。老师可以设定建议执行时间和下一次跟进安排。

记录区分草稿和已确认版本，家长看到老师确认的内容。下一次咨询复用孩子资料并新增记录，不覆盖前次记录和反馈。

## 7. 家长反馈与老师回复

家长针对某次咨询的执行建议提交文字反馈，说明“我是怎么做的、孩子有什么反应、遇到了什么困难”。同一建议可以多次反馈，每次保留内容与提交时间。

老师在工作台查看待回复反馈，逐条回复；家长可以继续补充。双方按时间查看全部执行记录与答复。后续跟进不能因旧文字咨询的 60 分钟计时结束而自动锁定。

## 8. 两种沟通总结

### 小程序内文字聊天

用户或老师进入对应咨询后，可以对本次双方可见的聊天内容生成总结草稿。总结关联本次咨询，记录消息范围和生成时间，不混入其他孩子、其他咨询或已撤回消息。

### 线下面谈录音

在取得参与者同意后显式开始录音，页面展示录音状态并支持停止。录音保存到受限访问的后端资产，转写后生成总结草稿；只总结实际采集的内容，不能直接读取没有录制的谈话。

### 共同规则

总结包含主要问题、沟通要点、待确认事项与执行建议。两种来源明确标识，可共同供老师整理本次记录。老师检查、修改并确认后才纳入正式记录；生成失败可重试或改为手动填写，不阻塞咨询与反馈。

## 10. 数据建模方案（尚未创建）

以下均为中文业务对象，尚未映射为 Zion API 表名。创建前必须核实实时 schema，关联由 Zion 关系生成，不手工猜测外键。

| 业务对象 | 主要内容 | 关联 |
| --- | --- | --- |
| 免费公开课场次 | 标题、时间、报名入口、进群说明、上下架状态 | 一场对应多份报名 |
| 公开课报名 | 姓名、手机、进群跟进、参加状态、核实人员和时间 | 账号、公开课场次；同账号同场次报名唯一 |

| 线下咨询预约 | 期望/确认时间、状态、基础信息快照 | 账号、孩子、老师、到课依据 |
| 咨询记录 | 本次内容、确认记录、完成时间 | 一次预约对应本次记录 |
| 沟通总结任务 | 来源、消息范围或录音、转写、任务状态、草稿、确认版本 | 对应咨询、发起账号、后端资产 |
| 执行建议 | 做法、可选章节、跟进安排 | 一次咨询对应多条建议 |

| 反馈回复 | 回复正文、发送时间、回复人 | 一份反馈对应多条回复 |

服务端统一校验当前账号、记录归属、工作人员身份与权限。参加确认和预约资格通过可信后台维护。姓名、手机号、孩子资料、录音与总结不公开读取。普通用户不能直接更新到课、预约确认或老师记录。

## 11. 验收场景

1. 免费公开课明确显示免费，报名只收集必要信息，不触发支付。
2. 姓名和手机号校验通过后才提交；网络失败不展示报名成功，重复提交不重复建档。
3. 报名成功可查看进群指引；工作人员可查看名单、登记进群和到课情况。
4. 只有报名但未参加的用户不能预约；直接调用接口也不能绕过资格检查。
5. 工作人员核实已参加后，用户可以提交申请；提交后为待确认。
6. 工作人员确认后才显示预约成功，并引导到店前填写孩子基础信息。
7. 多个孩子与历次咨询互相区分，修改基础信息不覆盖旧记录。
8. 老师能确认本次沟通记录与多条建议；家长可多次反馈，老师能逐条回复。
9. 旧咨询计时结束不阻断本次执行反馈；历史支付单不被当作公开课参加证明。
10. 文字总结只使用本次授权内容，录音经同意后开始；两种总结都经老师确认才成为正式记录。
11. 总结失败不阻塞手工记录；未经授权的账号不能查看其他家长的孩子资料、录音或记录。
12. 内部付费课程不成为当前流程入口或前置条件。
